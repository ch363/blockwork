# iOS Project Setup (T8.21)

This document covers setting up the iOS project for Blockwork on iPadOS and Apple Silicon Macs via "Designed for iPad".

## Prerequisites

- macOS with Xcode 15+ installed
- CocoaPods (`sudo gem install cocoapods`)
- Node 20+ and pnpm

## Initial Setup

The iOS project is generated by Capacitor. Run these commands from the repository root:

```bash
# Install dependencies
pnpm install

# Build the web app
pnpm build

# Navigate to the app package
cd packages/app

# Add the iOS platform (creates the ios/ directory)
pnpm exec cap add ios

# Sync web assets and native dependencies
pnpm exec cap sync ios

# Open in Xcode
pnpm exec cap open ios
```

## Xcode Configuration

After opening in Xcode, configure the following:

### 1. Signing & Capabilities

1. Select the App project in the navigator
2. Select the App target
3. Go to "Signing & Capabilities"
4. Set your Team (requires Apple Developer account)
5. Set the Bundle Identifier to `dev.blockwork.app`

### 2. Info.plist Configuration

Open `ios/App/App/Info.plist` and verify/add these entries:

```xml
<!-- iPadOS 26 window control overlap fix -->
<key>UIDesignRequiresCompatibility</key>
<true/>

<!-- App orientation support -->
<key>UISupportedInterfaceOrientations~ipad</key>
<array>
    <string>UIInterfaceOrientationLandscapeLeft</string>
    <string>UIInterfaceOrientationLandscapeRight</string>
    <string>UIInterfaceOrientationPortrait</string>
    <string>UIInterfaceOrientationPortraitUpsideDown</string>
</array>

<!-- Status bar style -->
<key>UIStatusBarStyle</key>
<string>UIStatusBarStyleLightContent</string>
<key>UIViewControllerBasedStatusBarAppearance</key>
<true/>
```

### 4. Launch Screen

The launch screen is configured in `ios/App/App/Base.lproj/LaunchScreen.storyboard`. Replace the default Capacitor launch screen with a branded version matching the app's background color (#14171c).

## Building and Running

### Development

```bash
# From repository root
pnpm build:ios

# Then in Xcode: Product > Run (⌘R)
```

### Device Testing

1. Connect your iPad
2. Select the device in Xcode's device picker
3. Build and run (⌘R)

### Designed for iPad (Apple Silicon Mac)

The app automatically runs on Apple Silicon Macs via "Designed for iPad":

1. Build for a generic iOS Device
2. Archive (Product > Archive)
3. Distribute for Development or App Store

## Safe Area Handling

Safe area insets are handled via CSS environment variables set in `index.html`:

```css
:root {
  --safe-area-inset-top: env(safe-area-inset-top, 0px);
  --safe-area-inset-right: env(safe-area-inset-right, 0px);
  --safe-area-inset-bottom: env(safe-area-inset-bottom, 0px);
  --safe-area-inset-left: env(safe-area-inset-left, 0px);
}
```

The UI respects these values for the top bar, dock, and inspector panel positioning.

## App Lifecycle

The app handles iOS lifecycle events via `@capacitor/app`:

- **Background** (`pause` event): Pauses simulation, triggers autosave
- **Foreground** (`resume` event): No auto-resume (player controls speed)

Additionally, the web `visibilitychange` event fires on backgrounding, providing redundant autosave coverage.

### Memory Warnings

iOS memory warnings are not exposed through the standard Capacitor App plugin. However, the aggressive autosave strategy (on every background, on visibility change, and on timed intervals via `autosaveHours` setting) means work is rarely more than a few minutes old.

For true memory warning handling, a native Swift plugin would be needed to observe `UIApplication.didReceiveMemoryWarningNotification`. This is not implemented in v1.

## Troubleshooting

### CocoaPods Issues

If `cap sync` fails with pod errors:

```bash
cd ios/App
pod install --repo-update
```

### SharedArrayBuffer

SharedArrayBuffer requires cross-origin isolation. The Capacitor WebView handles this automatically, but verify in the app's HUD that it shows "sab" (SharedArrayBuffer transport) rather than "postMessage".

### Build Failures

1. Clean build folder: Product > Clean Build Folder (⇧⌘K)
2. Delete derived data: `rm -rf ~/Library/Developer/Xcode/DerivedData`
3. Re-sync: `pnpm exec cap sync ios`
